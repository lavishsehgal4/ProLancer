📘 API: Get Services by Title (Pagination + Filters)

API URL:
GET http://localhost:8000/categories/:title

Authentication:
No authentication required

Description:
Fetches a paginated list of freelancer services based on a service title (case-insensitive). Supports filters like budget range, rating, experience level, and pagination. Used for Fiverr-style category pages.

PATH PARAMETERS:
| Name  | Type   | Required | Description |
|-------|---------|----------|-------------|
| title | String | Yes | Service title in slug format (e.g., "web-development"). Backend auto-converts this to "web development". |

QUERY PARAMETERS (ALL OPTIONAL):
| Query       | Type   | Required | Example        | Description |
|-------------|--------|----------|----------------|-------------|
| page        | Number | No       | 1              | Page number |
| limit       | Number | No       | 6              | Items per page |
| minRate     | Number | No       | 20             | Minimum hourly rate |
| maxRate     | Number | No       | 60             | Maximum hourly rate |
| rating      | Number | No       | 4              | Minimum rating |
| experience  | String | No       | intermediate   | "entry", "intermediate", "expert" |

EXAMPLE REQUEST:
GET http://localhost:8000/categories/web-development?page=1&limit=6&minRate=20&maxRate=60&rating=4&experience=intermediate

SUCCESS RESPONSE:
{
    "success": true,
    "title": "web development",
    "currentPage": 1,
    "totalPages": 3,
    "limit": 6,
    "totalItems": 18,
    "services": [
        {
            "serviceId": "675ac98b21e52c1bd48248cd",
            "title": "Web Development",
            "bio": "Building modern responsive web apps.",
            "hourlyRate": 40,
            "profilePicture": "https://example.com/pic.jpg",
            "averageRating": 4.7,
            "totalReviews": 22,
            "skills": ["React", "Node.js", "MongoDB"],
            "name": "John Doe"
        }
    ]
}

ERROR RESPONSES:

Missing title:
{
    "success": false,
    "message": "Service title is required in URL"
}

Server Error:
{
    "success": false,
    "message": "Server error in fetching services",
    "error": "..."
}

NOTES:
- "web-development" (slug) is auto-converted to "web development".
- Title comparison is case-insensitive.
- Supports filters for budget, rating, and experience.
- Returns paginated results with totalPages and totalItems.
- Each service includes: serviceId, title, bio, hourlyRate, profilePicture, averageRating, totalReviews, skills, name.


📘 API: Get Freelancer + Service Details from Service ID

API URL:
GET http://localhost:8000/categories/service/:serviceId

Authentication:
No authentication required

Description:
This API returns detailed information about a freelancer AND the specific service associated with the given serviceId.  
ServiceId is mapped through a separate collection (FreelancerServiceMap).  
Only the specific service is returned, not the entire services array.

PATH PARAMETERS:
| Name      | Type   | Required | Description |
|-----------|---------|----------|-------------|
| serviceId | String | Yes      | MongoDB ObjectId of the service you want to fetch |

QUERY PARAMETERS:
None

EXAMPLE REQUEST:
GET http://localhost:8000/categories/service/675ac98b21e52c1bd48248cd

SUCCESS RESPONSE:
{
  "success": true,
  "message": "Freelancer and service fetched successfully",
  "data": {
    "freelancerInfo": {
      "aboutMe": "Full-stack developer with 3 years experience.",
      "education": "B.Tech CSE 2022",
      "yearsOfExperience": 3,
      "averageRating": 4.8,
      "completedJobs": 42,
      "activeJobs": 3,
      "successRate": 97,
      
    },
    "service": {
      "_id": "675ac98b21e52c1bd48248cd",
      "title": "Web Development",
      "bio": "I build modern full-stack applications using MERN.",
      "description": "Detailed service description goes here...",
      "category": "web development",
      "skills": ["React", "Node.js", "MongoDB"],
      "hourlyRate": 40,
      "profilePicture": "https://example.com/service.jpg",
      "averageRating": 4.7,
      "totalReviews": 22,
      "isActive": true
    }
  }
}

ERROR RESPONSES:

1. Invalid or missing serviceId:
{
  "success": false,
  "message": "Service ID is required"
}

2. No mapping found:
{
  "success": false,
  "message": "No freelancer found for this serviceId"
}

3. No freelancer found:
{
  "success": false,
  "message": "Freelancer not found for this service"
}

4. Server error:
{
  "success": false,
  "message": "Server error",
  "error": "Detailed error message"
}

NOTES:
- serviceId must be a valid MongoDB ObjectId.
- API uses FreelancerServiceMap to find which freelancer owns the service.
- Only one service is returned using the MongoDB positional operator ("services.$").
- Perfect for service detail pages showing freelancer information + their service.




# FRONTEND TASK: Implement Google Login (Login Only)

Your backend exposes these endpoints:

1️⃣ Start Google Login  
GET http://localhost:8000/auth/google/login

2️⃣ Google Login Callback redirects to frontend:  
http://localhost:5173/auth/success?token=JWT

3️⃣ If user not registered, backend redirects to:  
http://localhost:5173/login?error=not_registered


## ✔️ TASK 1 — Create a "Login with Google" button

Create a React button that redirects user to:
http://localhost:8000/auth/google/login

Example:
<button onClick={() => window.location.href = "http://localhost:8000/auth/google/login"}>
  Login with Google
</button>


## ✔️ TASK 2 — Create a page: /auth/success

Create a component at:
src/pages/AuthSuccess.jsx

This page should:

1. Read token from URL:
const params = new URLSearchParams(window.location.search);
const token = params.get("token");

2. Store token:
localStorage.setItem("token", token);

3. Redirect user to dashboard:
navigate("/dashboard");


## ✔️ TASK 3 — Handle Errors on Login Page

On the login page, read URL query:
const params = new URLSearchParams(window.location.search);
if (params.get("error") === "not_registered") {
  show an alert or message: "Google account not registered. Please sign up first."
}

## ✔️ TASK 4 — Make every API request send JWT

Create axios instance:
axios.defaults.headers.common["Authorization"] = "Bearer " + localStorage.getItem("token");

## ✔️ SUMMARY

Flow should be:
Login Page → Click "Login with Google" →
Backend → Google →
Backend callback → Redirect to /auth/success?token=XYZ →
Save token → Redirect to dashboard →
Use token for all protected APIs.
